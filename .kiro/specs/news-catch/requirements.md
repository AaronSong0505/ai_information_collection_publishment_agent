# 需求文档

## 介绍

news_catch 是一个新闻抓取系统，旨在实时抓取全球新闻内容（包括文字/摘要和配图），将原始内容保存到本地存储，以便后续进行 AI 分析或二次处理。

**MVP 阶段策略：** 基于 NewsNow 开源项目进行快速验证，不限制特定行业，专注于核心抓取和存储功能。

**后续迭代计划：** 采用开源研究平台（如 Media Cloud、Apify）的技术路线，增加 AI 专业内容过滤、多语言支持和高级分析功能。

## 需求

### 需求 1

**用户故事：** 作为系统管理员，我希望能够配置多个新闻源，以便系统可以从不同的网站抓取新闻内容。

#### 验收标准

1. 当管理员添加新闻源配置时，系统应当验证URL的有效性并保存配置
2. 当管理员修改新闻源配置时，系统应当更新相应的抓取规则
3. 当管理员删除新闻源时，系统应当停止对该源的抓取并清理相关配置
4. 如果新闻源不可访问，系统应当记录错误日志并继续处理其他源

### 需求 2

**用户故事：** 作为系统用户，我希望系统能够自动定期抓取新闻，以便获得最新的新闻内容。

#### 验收标准

1. 当到达预设的抓取时间时，系统应当自动开始新闻抓取流程
2. 当抓取过程中遇到网络错误时，系统应当进行重试机制
3. 当抓取完成时，系统应当更新抓取状态和时间戳
4. 如果抓取频率过高导致被封禁，系统应当自动调整抓取间隔

### 需求 3

**用户故事：** 作为数据分析师，我希望抓取的新闻内容能够被结构化存储，以便后续的数据分析和处理。

#### 验收标准

1. 当新闻内容被抓取时，系统应当提取标题、正文、发布时间、来源、图片链接等关键信息
2. 当内容提取完成时，系统应当将数据以结构化格式存储到数据库和文件系统
3. 当遇到重复新闻时，系统应当进行去重处理
4. 如果内容解析失败，系统应当记录原始HTML并标记为待处理

### 需求 3.1 - 图片内容处理

**用户故事：** 作为数据分析师，我希望系统能够抓取和存储新闻配图，以便进行完整的内容分析。

#### 验收标准

1. 当检测到新闻包含图片时，系统应当下载并保存图片到本地文件系统
2. 当图片下载完成时，系统应当在数据库中记录图片的本地路径和原始URL
3. 当图片下载失败时，系统应当记录错误信息但不影响文本内容的处理
4. 如果图片格式不支持，系统应当记录格式信息并跳过下载

### 需求 4

**用户故事：** 作为系统用户，我希望能够搜索和查看抓取的新闻内容，以便快速找到感兴趣的信息。

#### 验收标准

1. 当用户输入搜索关键词时，系统应当返回相关的新闻列表
2. 当用户查看新闻详情时，系统应当显示完整的新闻内容和元数据
3. 当用户按时间范围筛选时，系统应当返回指定时间段内的新闻
4. 如果搜索结果为空，系统应当显示友好的提示信息

### 需求 5

**用户故事：** 作为系统管理员，我希望能够监控抓取系统的运行状态，以便及时发现和解决问题。

#### 验收标准

1. 当抓取任务执行时，系统应当记录详细的运行日志
2. 当出现异常情况时，系统应当发送告警通知
3. 当查看系统状态时，系统应当显示各新闻源的抓取统计信息
4. 如果系统资源使用过高，系统应当自动限制并发抓取数量

### 需求 6 - MVP 阶段实时性要求

**用户故事：** 作为系统用户，我希望系统能够提供近实时的新闻更新，以便及时获取最新信息。

#### 验收标准

1. 当系统运行时，新闻更新延迟应当控制在几分钟以内
2. 当设置抓取间隔时，系统应当支持最短2分钟的采集间隔
3. 当内容更新时，系统应当提供30分钟的默认缓存机制
4. 如果网络延迟较高，系统应当优先保证数据完整性而非速度

### 需求 7 - 基于 NewsNow 的 MVP 实现

**用户故事：** 作为开发人员，我希望基于 NewsNow (ourongxing/newsnow) 开源项目快速构建 MVP 版本，以便验证核心功能。

#### 验收标准

1. 当部署系统时，应当基于 NewsNow 的 Node.js + Cloudflare D1 架构实现优雅的新闻阅读体验
2. 当系统启动时，应当继承 NewsNow 的 MCP Server 架构、实时热门新闻聚合和缓存机制
3. 当扩展功能时，应当在 NewsNow MIT License 基础上进行开发，保持整洁的 UI 设计
4. 如果需要定制化，应当保持与原项目的兼容性以便后续升级和功能扩展

### 需求 8

**用户故事：** 作为开发人员，我希望系统具有良好的扩展性，以便能够轻松添加新的新闻源和处理规则。

#### 验收标准

1. 当添加新的新闻源类型时，系统应当支持插件化的解析器扩展
2. 当需要自定义抓取规则时，系统应当提供配置化的选择器设置
3. 当集成第三方API时，系统应当提供统一的接口适配层
4. 如果解析规则发生变化，系统应当支持热更新而无需重启

### 需求 9 - 后续迭代准备

**用户故事：** 作为产品规划者，我希望系统架构能够支持后续向开源研究平台技术路线的迁移。

#### 验收标准

1. 当设计数据模型时，应当考虑与 Media Cloud 和 Apify 平台的兼容性
2. 当实现核心功能时，应当预留 AI 内容过滤和多语言支持的扩展接口
3. 当存储数据时，应当使用标准化格式以便后续数据迁移
4. 如果需要重构，应当确保现有数据和配置的平滑迁移
